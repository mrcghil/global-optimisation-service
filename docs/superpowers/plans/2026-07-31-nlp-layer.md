# NLP Core Layer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `nlp/` layer — an `NLPProblem` that wraps a single `ad::ADBackend` and presents the exact quantities a nonlinear solver (IPOPT) needs: objective, constraints, objective gradient, sparse constraint Jacobian, and sparse Lagrangian Hessian, all with bounds.

**Architecture:** `NLPProblem` owns ONE `ADBackend` whose recorded function packs the objective in output 0 and the `m` constraints in outputs 1..m. That single recording supplies everything: objective = `eval(x)[0]`; constraints = `eval(x)[1..m]`; objective gradient = Jacobian row 0 scattered dense; constraint Jacobian = Jacobian rows 1..m re-indexed; Lagrangian Hessian = `eval_hessian(x, [obj_factor, λ...])` — the backend's weighted-sum Hessian is *exactly* `obj_factor·∇²f + Σλᵢ∇²gᵢ`. `NLPProblem` depends only on the `ADBackend` *interface*, never on CppADCodeGen, keeping the core backend-agnostic.

**Tech Stack:** C++17, the merged `goss::ad` layer (ADBackend interface + CppADCGBackend for tests), Eigen (available, not required here), GoogleTest, CMake, containerized build via `scripts/dev.sh`.

## Global Constraints

- Language: **C++17**.
- `NLPProblem` MUST depend only on `goss::ad::ADBackend` (the abstract interface) and `goss::ad::types` — NEVER on `CppADCGBackend` or any CppAD/CppADCodeGen type. Backend-neutrality is load-bearing.
- The packing convention is fixed: **output 0 is the objective; outputs 1..m are the `m` constraints.** Every method relies on this.
- Sparse outputs carry a sparsity pattern (values + `SparsityPattern` from `goss::ad::types`); `eval_*` values MUST align index-for-index with the corresponding `*_sparsity()` pattern, matching the alignment contract the `ad/` layer already documents.
- Objective gradient is returned DENSE (size `num_variables()`) — that is the form IPOPT's `eval_grad_f` wants.
- Constraint Jacobian and Lagrangian Hessian are returned SPARSE.
- Error handling per org standard: a specific `NLPError` exception with meaningful messages; validate dimensions at construction; runtime guards active in release builds (throw, do not `assert`). No silent catch-all.
- Coding standards: verbose descriptive variable names; type annotations everywhere; comments explain WHY.
- Container-first build: all `cmake`/`ctest` run inside the container via `scripts/dev.sh '<command>'`. Never build on the host.
- Test framework: **GoogleTest**. Tests may construct a concrete `CppADCGBackend` (packed functor) to feed `NLPProblem`, since a real backend is the honest fixture.

```cpp
#include "goss/nlp/nlp_problem.hpp"
#include <string>

namespace goss::nlp {

NLPProblem::NLPProblem(std::unique_ptr<ad::ADBackend> backend,
                       std::vector<double> variable_lower_bounds,
                       std::vector<double> variable_upper_bounds,
                       std::vector<double> constraint_lower_bounds,
                       std::vector<double> constraint_upper_bounds)
    : backend_(std::move(backend)),
      variable_lower_bounds_(std::move(variable_lower_bounds)),
      variable_upper_bounds_(std::move(variable_upper_bounds)),
      constraint_lower_bounds_(std::move(constraint_lower_bounds)),
      constraint_upper_bounds_(std::move(constraint_upper_bounds)) {
    if (!backend_) {
        throw NLPError("NLPProblem: backend must not be null");
    }
    if (backend_->output_size() < 1) {
        throw NLPError("NLPProblem: backend output_size must be >= 1 (output 0 is the objective)");
    }
    num_variables_ = backend_->input_size();
    num_constraints_ = backend_->output_size() - 1;

    if (variable_lower_bounds_.size() != num_variables_ ||
        variable_upper_bounds_.size() != num_variables_) {
        throw NLPError("NLPProblem: variable bound vectors must have size == num_variables (" +
                       std::to_string(num_variables_) + ")");
    }
    if (constraint_lower_bounds_.size() != num_constraints_ ||
        constraint_upper_bounds_.size() != num_constraints_) {
        throw NLPError("NLPProblem: constraint bound vectors must have size == num_constraints (" +
                       std::to_string(num_constraints_) + ")");
    }
    for (std::size_t i = 0; i < num_variables_; ++i) {
        if (variable_lower_bounds_[i] > variable_upper_bounds_[i]) {
            throw NLPError("NLPProblem: variable " + std::to_string(i) +
                           " has lower bound > upper bound");
        }
    }
    for (std::size_t i = 0; i < num_constraints_; ++i) {
        if (constraint_lower_bounds_[i] > constraint_upper_bounds_[i]) {
            throw NLPError("NLPProblem: constraint " + std::to_string(i) +
                           " has lower bound > upper bound");
        }
    }
}

}  // namespace goss::nlp
```

### Task 4: Objective gradient (dense) from Jacobian row 0

**Files:**
- Modify: `include/goss/nlp/nlp_problem.hpp`
- Modify: `src/nlp/nlp_problem.cpp`
- Modify: `tests/nlp/test_nlp_eval.cpp`

**Interfaces:**
- Consumes: `backend_->jacobian_sparsity()` (const `SparsityPattern&`, (row,col) pairs aligned to values), `backend_->eval_jacobian(x)` (values aligned to that pattern).
- Produces:
  - `std::vector<double> eval_objective_gradient(const std::vector<double>& x) const;` → DENSE vector of size `num_variables_`; entry `col` = the Jacobian value whose sparsity entry is `(0, col)`; entries with no `(0, col)` structural nonzero are `0.0`.
  - Precompute at construction: a vector `objective_gradient_slots_` where, for each `k` in the backend's jacobian sparsity, if `row == 0`, record the pair `(col, k)` so `eval_objective_gradient` can scatter `values[k]` into `gradient[col]` in O(nnz_row0). Store as `std::vector<std::pair<std::size_t,std::size_t>>` (col, value_index).

**Design note:** The backend's Jacobian is over ALL outputs (objective + constraints). Row 0 of that Jacobian is ∇f. We do NOT re-record a separate objective function — one recording, filtered by row. This is the whole point of the packing convention.

std::vector<double> NLPProblem::eval_objective_gradient(const std::vector<double>& x) const {
    if (x.size() != num_variables_) {
        throw NLPError("eval_objective_gradient: x.size() != num_variables");
    }
    const std::vector<double> jacobian_values = backend_->eval_jacobian(x);
    std::vector<double> gradient(num_variables_, 0.0);
    for (const auto& [col, value_index] : objective_gradient_slots_) {
        gradient[col] = jacobian_values[value_index];
    }
    return gradient;
}

**Interfaces:**
- Consumes: `backend_->jacobian_sparsity()`, `backend_->eval_jacobian(x)`.

### Task 6: Sparse Lagrangian Hessian via the backend's weighted-sum Hessian

**Files:**
- Modify: `include/goss/nlp/nlp_problem.hpp`
- Modify: `src/nlp/nlp_problem.cpp`
- Modify: `tests/nlp/test_nlp_eval.cpp`

**Interfaces:**
- Consumes: `backend_->hessian_sparsity()` (lower-triangle (row,col), col<=row, aligned to values), `backend_->eval_hessian(x, weights)` where `weights.size() == output_size()` and the result is `Σ weights[i]·∇²(output_i)`.
- Produces:
  - `const ad::SparsityPattern& lagrangian_hessian_sparsity() const;` → identical to the backend's `hessian_sparsity()` (lower-triangle over the variable space; the Hessian is w.r.t. `x` only, so no re-indexing is needed).
  - `std::vector<double> eval_lagrangian_hessian(const std::vector<double>& x, double objective_factor, const std::vector<double>& constraint_multipliers) const;`
    - Validates `x.size() == num_variables_` and `constraint_multipliers.size() == num_constraints_`, else `NLPError`.
    - Builds `weights` of size `output_size()` = `num_constraints_ + 1`: `weights[0] = objective_factor`, `weights[1 + i] = constraint_multipliers[i]`.
    - Returns `backend_->eval_hessian(x, weights)` directly — the weighted sum over packed outputs is exactly `objective_factor·∇²f + Σ λ_i·∇²g_i`, the Lagrangian Hessian IPOPT's `eval_h` wants. Values align to `lagrangian_hessian_sparsity()`.

**Design note (the crux):** This is why the packing convention exists. Because the objective sits in output 0 and constraints in 1..m, the backend's single weighted-sum Hessian, fed `[obj_factor, λ...]`, IS the Lagrangian Hessian — no separate Hessian assembly, no summing of per-constraint Hessians in this layer. The `ad/` layer already returns lower-triangle only, which matches IPOPT's expected format.

std::vector<double> NLPProblem::eval_lagrangian_hessian(
    const std::vector<double>& x,
    double objective_factor,
    const std::vector<double>& constraint_multipliers) const {
    if (x.size() != num_variables_) {
        throw NLPError("eval_lagrangian_hessian: x.size() != num_variables");
    }
    if (constraint_multipliers.size() != num_constraints_) {
        throw NLPError("eval_lagrangian_hessian: constraint_multipliers.size() != num_constraints");
    }
    std::vector<double> weights(num_constraints_ + 1);
    weights[0] = objective_factor;
    for (std::size_t i = 0; i < num_constraints_; ++i) {
        weights[1 + i] = constraint_multipliers[i];
    }
    return backend_->eval_hessian(x, weights);
}
